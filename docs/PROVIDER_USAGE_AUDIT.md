# Provider usage audit

The API and freshness worker record one event for each actual Moonshot HTTP attempt made through `LiveKimiProvider._chat` or the Kimi vision transport. This includes route generation, source comparisons, source discovery, chat composition, direct translation/catalog calls, document work, and vision OCR. Retries are separate attempts. Standalone external audit scripts that bypass these application providers are outside this ledger.

Set `ELLIS_PROVIDER_USAGE_LOG` to the same private, writable path for both processes. The default is `/var/lib/ellis/provider_usage.jsonl` when that state directory exists; otherwise it is `provider_usage.jsonl` under `ELLIS_DATA_DIR` or `data`. Keep this file outside the served web directory. It is created with mode 0600 and guarded with an interprocess file lock. Root logger levels and disabled HTTP access logging do not suppress these events.

Each event contains UTC time, a unique attempt ID, PID/process instance, static caller function names, requested and returned model names, HTTP status, provider request/response identifiers, duration, and available numeric usage metrics. A 16-character SHA256 credential fingerprint distinguishes rotated keys without storing any key characters. Raw `cached_tokens` and nested cached-prompt metrics remain separate; they are never added together. Missing usage is unknown, not zero. The ledger makes no dollar estimate and is not a replacement for the provider's bill.

Prompts, images, applicant text, full responses, exception messages, credentials, authorization headers, caller arguments, and complete URLs are excluded. Identifiers accept only a bounded character vocabulary and reject credential-like values.

Requests enqueue metadata without waiting for disk or file locks. A daemon writer appends and fsyncs it. Each process has a bounded 1,024-event queue and a one-second graceful-shutdown drain. Successful appends are durable; abrupt termination, a prolonged sink outage, or a full queue can lose events. Cumulative dropped/failed/written counts appear in subsequent ledger records as `audit_delivery`; `delivery_status()` exposes the process-local pending count too. Write failures produce a safe warning containing only the exception class. A lost event or missing provider usage must not be reported as zero consumption. No automatic rotation is used, avoiding separate processes racing to rotate one file; operators should manage retention outside active writes.

Public research accepts the same finite purpose/document vocabulary as lookup. Translation requests accept up to 100,000 text characters. Catalog requests preserve the complete shipped catalog, with at most 2,000 entries, 80-character keys, 1,000 characters per value, and 320,000 total text characters. These are input-shape bounds, not a spending allowance, rate limit, or monthly budget. Public QC remains available.
