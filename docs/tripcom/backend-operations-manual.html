Ellis 信息质量管控后台 操作手册

Ellis Information Quality Control Backend, Operations Manual · 版本 2026-09-01 · 交付物清单第10项 Deliverable No. 10

1. 访问方式 Access

浏览器打开 https://ellis-visa.com，点击右上角「质控台」进入后台。无需安装，无需配置，无需申请账号。测试权限已预置。

Open https://ellis-visa.com in a browser and press "Quality console" in the header. No install, no setup, no account application. Test access is preconfigured.

右上角地球图标可切换语言：English、简体中文、繁體中文。界面与数据说明同步切换。

The globe icon switches the language: English, Simplified Chinese, Traditional Chinese.

Records 页承载全量抽查。筛选条件可任意组合：

The Records tab carries the full spot check. Filters combine freely:

The four tiles follow the current filter: record count, completeness, source coverage, confidence split. The completeness tile shows both calibers: fillable (excluding does-not-apply and not-published cells) and the literal count over required cells.

The flag form at the bottom of the card files a field-level issue straight into the correction queue.

2b. 新增线路与编辑字段 Adding routes and editing fields

Records 页的「新增线路」卡片让运营自行加入任意国家组合：选择护照、目的地、出行目的与证件类型，点一次按钮。已有线路即时返回，全新线路约一分钟内作答并进入记录列表，列表自动筛选到该线路。低置信度的新答案会先拦截，经核对官方来源后展示。

The Add a route card on the Records tab lets operations add any country pair themselves: pick the passport, destination, purpose and document, and press once. Known routes return instantly, brand new ones answer within about a minute and join the record list, already filtered into view. A low-confidence new answer is held until checked against the official source.

展开任意记录，点「编辑字段」可直接修改该线路：只填想改的字段（停留、费用、办理时长、材料、注意事项等），并必须附上支持本次修改的官方页面网址与说明。保存即生效，下一位读者立刻看到修改后的值，修改人、日期与来源随记录展示，变更记录同步留痕。非官方域名的来源会被拒绝。

Expand any record and press Edit fields to change the route directly: fill only the fields to change, and attach the official page URL that backs the edit plus a note. Saving takes effect immediately for the next reader, with the editor, date and source shown on the record and an entry written to the change log. A non-government source URL is refused.

3. Correction queue 纠错队列 The five-stage loop

每条问题沿验收标准4.1.2的五个阶段推进，每个阶段一个按钮，顺序不可跳过：

Every issue walks the five stages of standard 4.1.2, one button per stage, no skipping:

1标记 open。读者或运营在记录上发起。
A reader or operator flags a field.
2已通知信息方 acknowledged。记录信息提供方已获知。
The information provider has been told.
3已修正 corrected。写明修正内容后提交。旧答案立即从服务中撤下。
The fix is written and the old answer is withdrawn at once.
4已复核 reviewed。必须由修正人以外的运营复核，系统强制。
A second operator reviews. The system enforces the separation.
5发布上线 published。修正后的答案对读者生效。
The corrected answer goes live.

任一阶段可选择「不处理 dismissed」，但必须写明原因。整个闭环目标不超过48小时，每个阶段的时间戳都被记录，可导出核验。

Dismissal needs a written reason at any stage. The end-to-end target is 48 hours and every stage is timestamped.

4. Change log 变更记录 Add, modify, delete

每次影响读者可见内容的更新自动写入变更记录，区分新增、修改、删除三类，修改类带逐字段前后对照。答案因纠错被撤下时会写入删除记录。支持全文搜索，覆盖全部历史。

Every reader-visible update writes a change entry: add, modify or delete, with field-level diffs. Withdrawing an answer through the correction loop writes a delete entry. Search runs over the full history.

5. AI 问答抽查 Sampling the assistant

AI 问答页列出智能助手实际回答过的每一次交互：问题原文、读取的线路、给出的答案、引用来源。运营对每条可作裁定：

The AI Q&A tab lists every exchange the assistant actually served: the question, the route it was read as, the answer and the cited source. Each exchange takes a ruling:

正确 correct 记录复核人与时间。
有误 wrong 必须写明问题所在，系统自动就该线路立一条纠错队列问题，走完整闭环。

Ruling an answer wrong requires a written reason and files a tracked issue on the answered route automatically.

6. Freshness 时效监控 The freshness monitor

系统定期重读官方页面。与记录一致则重新盖章。与人工核验事实不一致时不会自动改写，而是生成一条争议，附页面原文、当前记录值与引文，等待人工裁定。裁定后走纠错队列发布。页面上方的可用性卡片展示当月按分钟计的在线率。

Official pages are re-read on a schedule. Agreement restamps the record. Disagreement with a human-verified fact files a dispute with the page quote for a human ruling instead of overwriting. The availability tile shows the month's per-minute uptime.

7. 批量导出 Batch export

Records 页的「导出 Excel」按当前筛选条件导出 .xlsx。文件含两张工作表：数据表（25字段+来源+置信度）与字段说明表。字段说明表首行标注快照时间（UTC）。导出无行数上限，工作簿构建在12,000行实测1.2秒。

Export Excel follows the active filters. Two sheets: data (25 fields plus sources plus confidence) and field descriptions, stamped with the UTC snapshot time. No row cap exists in code. Workbook build measured 1.2 seconds at 12,000 rows.

8. 低置信度拦截与放行 Holds and release

按4.2.3分级为「低」的答案不对读者展示，读者只会看到「正在核对该线路」。放行有两条路：一是研究后写入经官方来源核验的事实（推荐），二是运营在核对官方页面后手动放行。两条路都会留下可审计的记录。

A Low-graded answer is withheld and the reader sees "We are checking this route". Release happens by writing source-verified facts (preferred) or by an audited manual release after checking the official page.

9. 深链 Deep links

数据库每条线路有稳定链接，形如 #database/CHN/JPN/tourism。链接可直接分享，打开即达对应记录页。

Every route has a stable deep link that opens the record page directly.

遇到与官方页面不一致的内容，请直接在记录上标记问题。这是最快的修正通道，全程可追踪，目标48小时内闭环。
If anything disagrees with an official page, flag it on the record. That is the fastest correction channel, fully tracked, with a 48 hour closure target.
