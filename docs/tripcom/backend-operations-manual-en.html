Ellis Information Quality Control Backend: Operations Manual

Version 3 September 2026 · Deliverable No. 10 · Maintained in step with the live system at ellis-visa.com

1. Access

Open https://ellis-visa.com in a browser and press "Quality console" in the header. No install, no setup, no account application. Test access is preconfigured.

The globe icon in the header switches the language between English, Simplified Chinese and Traditional Chinese. The interface and the data descriptions switch together.

2. Records: the multi-dimensional spot check

The Records tab carries the full spot check. Filters combine freely:

FilterWhat it does
PassportThe station dimension. Type a country name or a code, for example China, CHN or CN. Chinese names work too.
DestinationSame input rules. Typing KOR or South Korea returns only South Korea records.
PurposeTourism, business, family visit, study, work, transit, other.
Visa requirementThe top-level class: visa-free, on arrival, required in advance, conditional.
ConfidenceHigh, medium, low.
Visa typeSubstring match on the product name, for example "tourist".
Passport typeThe 13 travel document types, from ordinary to diplomatic passports.
Missing fieldShows only records where a given field is still missing. Used for gap-filling work.

Four tiles follow the current filter: record count, completeness, source coverage and the confidence split. The completeness tile shows both calibers: the fillable reading, whose denominator excludes cells marked "does not apply" and "not published", and the literal count over all required cells.

Click any row to expand the full 25-field record. Every field carries a status:

fillednot publisheddoes not applymissing

The flag form at the bottom of the card files a field-level issue straight into the correction queue.

3. Adding routes and editing fields

The "Add a route" card on the Records tab offers two ways in:

1Add with Ellis AI. Pick the passport, destination, purpose and document type and press once. Ellis answers the route and checks it against the official pages in the same move. The result lands in the records list. A low-confidence answer is held until it has been checked.
2Manual entry. Switch to manual and type the fields yourself: fee, stay, processing time, documents and the rest. An official source URL and a short note are required. The record serves immediately, with "Trip.com operations" recorded as its provenance.

Every expanded record has three buttons:

Edit fieldsopens a form covering every editable field: the verdict dropdowns, this visa row's validity, entries and fee, money and stay, how to apply, the arrival card, and the "not published" checkboxes. It is prefilled with the current values and writes only what changed.
Refresh from sourcehas Ellis re-read the official page on the spot. When nothing changed it says so plainly: "still current, no refresh needed". When the page differs, the record is corrected from the page and the change is logged with the quote.
Flagfiles a human report. Ellis then reads the official page itself and places what it found in the correction queue as a proposal. An operator accepts it in one click, which writes a sourced correction the next reader sees immediately, or declines it.

4. Correction queue: the five-stage loop

Every issue walks the five stages of standard 4.1.2, one button per stage, in order, with no skipping:

1Open. A reader or an operator flags a field on a record.
2Acknowledged. The information provider has been told.
3Corrected. The fix is written and the old answer is withdrawn from service at once.
4Reviewed. A second operator reviews. The system enforces that the reviewer is not the corrector.
5Published. The corrected answer goes live for readers.

An issue can be dismissed at any stage, but only with a written reason. The end-to-end target is 48 hours. Every stage is timestamped, and the timestamps export for verification.

5. Change log: add, modify, delete

Every update that changes what readers see writes a change entry, classed as add, modify or delete. Modifications carry field-level before and after values. Withdrawing an answer through the correction loop writes a delete entry. Search runs over the full history.

6. AI Q&A: sampling the assistant

The AI Q&A tab lists every exchange the assistant actually served: the question as asked, the route it was read as, the answer given and the source cited. Each exchange takes a ruling:

correct records the reviewer and the time.
wrong requires a written reason and automatically files a tracked issue on the answered route, which then walks the full correction loop.

7. Freshness: the automatic re-check

Ellis re-reads every served answer against its official page at least every 48 hours. A scheduled sweep runs several times a day and takes the oldest records first, so the whole database is re-read well inside 48 hours without hammering any government site.

When the page agrees with the record, the record is restamped. When the page differs from a value the machine holds, the record is corrected from the page with the quote saved. When the page differs from a human-verified fact, nothing is overwritten: a dispute is filed with the page quote, the current record value and the source, and a person rules on it through the correction queue.

The Freshness tab opens with a countdown to the next automatic re-check run, read from the scheduler itself rather than estimated, and shows how much of the database was re-read in the last 48 hours. The availability tile shows the month's uptime measured by the minute.

8. Batch export

"Export Excel" on the Records tab exports an .xlsx file following the active filters. The workbook has two sheets: the data sheet (25 fields plus sources plus confidence) and a field description sheet whose first row carries the snapshot time in UTC. There is no row cap in the code. Building a 12,000-row workbook measured 1.2 seconds.

9. Holds and release

An answer graded Low under standard 4.2.3 is never shown to readers. They see "We are checking this route" instead. There are two ways to release it: write a fact verified against an official source (preferred), or release it manually after checking the official page. Both leave an auditable record.

10. Deep links

Every route has a stable link of the form #database/CHN/JPN/tourism. The link can be shared directly and opens the record page.

If anything disagrees with an official page, flag it on the record. That is the fastest correction channel, fully tracked, with a 48-hour closure target.
